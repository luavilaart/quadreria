# Spanish and English

quadreria ships in Spanish and English. Spanish is written with **voseo** (vos), as spoken in Honduras: "Entrá", "Elegí", "¿Qué querés hacer?", "Unite".

## Where copy lives

| File | What it holds |
| --- | --- |
| `src/i18n/en.ts` | English copy. Its shape is the `Copy` type. |
| `src/i18n/es.ts` | Spanish copy. Typed as `Copy`, so a missing key fails the build. |
| `src/i18n/accounts.ts`, `accounts.es.ts` | Sign-up quiz, studio and account copy. |
| `src/i18n/index.ts` | Language detection, `useT()`, `useFormat()`, `useSetLang()`. |

## Rules for new code

- In a component, read copy with `const t = useT()`. Never import `en` directly in UI code.
- In a route `head()`, use `copyFor(langOf(match.context))`.
- Store stable values in the database (for example the medium `"Painting"`). Show them through `useFormat()`: `f.medium()`, `f.city()`, `f.eventType()`, `f.price()`, `f.date()`, `f.service()`.
- Copy that needs a name or number inside it is a small function, for example `t.event.left(spots, capacity)`.
- Artist content (titles, bios, FAQ) is shown as the artist wrote it. It is not translated.

## How the language is chosen

1. A saved choice in the `q-lang` cookie.
2. Otherwise the browser's languages: Spanish if it lists Spanish first among the two, English if it lists English, English for any other language.
3. Otherwise (no header, for example most crawlers) Spanish.

The server sets the cookie on first visit so the page hydrates in the same language. The ES/EN switch in the header and the join quiz saves the cookie and reloads route data, so titles and `<html lang>` change too.

## Tests

`src/test/i18n.test.ts` checks that both languages have the same keys, that no Spanish string is empty, that Spanish uses vos and not tú, and that every medium, city and event type has a Spanish label.
